# M1.4 — Retrieval Validation

## Evaluation protocol

Use two knowledge domains, for example:

1. Machine Learning
2. Computer Networks

Prepare questions of four types:
- Factual
- Procedural
- Comparative
- Unavailable-information

For every question, record the expected source/chunk and compare it with the retrieved Top-1, Top-3 and Top-5 results.

### Metrics

For N test questions:

`Top-K Accuracy = questions where the expected source appears in the first K results / N`

Report the result as a percentage.

## Limitations
- Character-based chunks can split semantic units.
- One embedding model may not perform equally well across domains.
- Pure vector similarity does not guarantee factual correctness.
- Unavailable-information detection needs a calibrated confidence threshold.
- Scanned/image-only PDFs require OCR, which is outside the basic M1 implementation.

## Proposed M2 improvements
- Better semantic/structure-aware chunking.
- Hybrid keyword + vector retrieval.
- Reranking.
- Confidence thresholds and stronger unavailable-answer handling.
- Full LLM response generation with citations.
- More robust multi-agent orchestration.
