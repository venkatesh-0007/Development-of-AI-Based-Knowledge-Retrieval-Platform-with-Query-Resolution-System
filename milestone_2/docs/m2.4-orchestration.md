# M2.4: Multi-Agent Orchestration Layer

## 1. Overview

The **Multi-Agent Orchestrator (M2.4)** manages the end-to-end sequential control flow across all specialized agents:
1. **Query Understanding Agent (M2.1)**
2. **Clarification Agent** (conditional branch for ambiguous queries)
3. **Retrieval Agent (M2.2)**
4. **Response Generation Agent (M2.3)**

---

## 2. Sequential Control Flow Architecture

```text
┌────────────┐
│ User Query │
└─────┬──────┘
      │
      ▼
┌─────────────────────────────────┐
│ Query Understanding Agent (M2.1)│
└─────┬───────────────────────────┘
      │
      ├───────────────────────────────┐
      │ IF route == "clarification"   │ IF route == "retrieval"
      ▼                               ▼
┌─────────────────────────┐     ┌───────────────────────┐
│   Clarification Agent   │     │  Retrieval Agent(M2.2)│
└─────┬───────────────────┘     └─────┬─────────────────┘
      │                               │
      │                               ▼
      │                         ┌────────────────────────────────────┐
      │                         │ Response Generation Agent (M2.3)   │
      │                         └─────┬──────────────────────────────┘
      │                               │
      └───────────────┬───────────────┘
                      ▼
        ┌───────────────────────────┐
        │    OrchestrationResult    │
        │  • Grounded Answer        │
        │  • Confidence Meter       │
        │  • Intent Badge           │
        │  • Source Citations       │
        │  • Execution Latency      │
        └───────────────────────────┘
```

---

## 3. Key Orchestration Features

1. **Deterministic State Propagation**: Each agent accepts strongly typed Pydantic/dataclass inputs and produces structured outputs without out-of-band side effects.
2. **Early Ambiguity Bypass**: Ambiguous or underspecified queries skip vector retrieval and embedding generation entirely, reducing latency and compute overhead.
3. **End-to-End Latency Tracking**: Records execution time in milliseconds (`execution_time_ms`) for profiling.
4. **Resilient Error Recovery**: Catches and wraps unexpected runtime exceptions into a user-safe `OrchestrationResult(status="error")` payload.

---

## 4. End-to-End Pipeline Performance

| Phase | Avg Latency (Pure Python / Local Embeddings) | Output Payload |
|---|:---:|---|
| **Query Understanding** | $< 0.5\text{ ms}$ | `QueryAnalysisResult` |
| **Vector Retrieval (ChromaDB)** | $10 - 25\text{ ms}$ | `RetrievalResult` |
| **Response Generation & Attribution** | $< 1.0\text{ ms}$ (Deterministic) | `AgentResponse` |
| **Total End-to-End Pipeline** | **$12 - 30\text{ ms}$** | `OrchestrationResult` |
