# M4.1 — Query Analytics and Knowledge Gap Detection System

## 1. Overview
The Query Analytics module provides independent, persistent operational telemetry for every query evaluated by the platform. The analytics system operates as a zero-overhead observer decoupled from the primary vector store and LLM generation loop.

All telemetry records are stored in a dedicated SQLite database located at:
`data/analytics/analytics.db`

---

## 2. Key Architecture & Components

```
User Query Execution (MultiAgentOrchestrator)
                    │
                    ▼
          AnalyticsTracker
                    │
    ┌───────────────┴───────────────┐
    ▼                               ▼
QueryLogEntry Construction      Resolution Status Classifier
    │                               │
    └───────────────┬───────────────┘
                    ▼
          AnalyticsStorage (SQLite)
                    │
    ┌───────────────┴───────────────┐
    ▼                               ▼
Query History & Filters      KnowledgeGapDetector
```

### Components
1. **`AnalyticsStorage` (`milestone_4/app/analytics/storage.py`)**:
   - Manages SQLite tables: `query_logs` and `knowledge_gaps`.
   - Performs indexed queries by timestamp, domain, query type, confidence level, and status.
   - Provides aggregation methods for KPI summaries and JSON/CSV export.
2. **`AnalyticsTracker` (`milestone_4/app/analytics/tracker.py`)**:
   - Intercepts `OrchestrationResult` objects.
   - Records granular telemetry including resolution path, agent sequence, retrieval metrics, confidence, and latency.
3. **`AnalyticsAnalyzer` (`milestone_4/app/analytics/analyzer.py`)**:
   - Computes real-time KPIs, distributions, and domain cross-tabulations.
4. **`KnowledgeGapDetector` (`milestone_4/app/analytics/gap_detector.py`)**:
   - Analyzes query logs to discover recurring unanswered queries and thematic gaps.

## 3. Logged Telemetry Fields
Every query execution records:
- `query_id`: Unique identifier (e.g., `qry_a1b2c3d4e5f6`)
- `session_id`: Client session identifier for conversation continuity
- `timestamp`: UTC ISO-8601 timestamp
- `query_text`: Original raw user input
- `effective_query`: Contextualized / coreference-resolved query
- `query_type`: Classified intent (`factual`, `procedural`, `comparative`, `ambiguous`, `multi_part`)
- `domain`: Knowledge domain (`machine_learning`, `computer_networks`, `cybersecurity`, `general`)
- `resolution_path`: Multi-agent path taken (e.g. `Query Understanding -> Retrieval -> Response Generation`)
- `agent_sequence`: Array of agents involved
- `retrieved_chunk_ids`: List of chunk IDs retrieved
- `sources`: Unique document names cited
- `source_count`: Number of sources cited
- `top_score`: Highest similarity score among retrieved chunks
- `avg_score`: Average similarity score among retrieved chunks
- `confidence_score`: Centralized confidence score `[0.0, 1.0]`
- `confidence_level`: Calibrated level (`HIGH`, `MEDIUM`, `LOW`, `NONE`)
- `status`: Resolution classification (`RESOLVED`, `LOW_CONFIDENCE`, `UNANSWERED`, `CLARIFICATION_REQUESTED`, `CLARIFICATION_RESOLVED`, `ERROR`)
- `latency_ms`: Total end-to-end execution time in milliseconds
- `input_modality`: Input channel (`text` or `voice`)
- `error`: Error details if applicable
