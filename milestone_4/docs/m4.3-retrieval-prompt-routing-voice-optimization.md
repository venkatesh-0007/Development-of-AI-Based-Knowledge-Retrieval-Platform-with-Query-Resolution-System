# Milestone 4.3: Retrieval, Prompt, Agent Routing and Voice Interaction Optimization

## 📌 Optimization Scope
Milestone 4.3 focuses on end-to-end performance calibration of the AI-based knowledge retrieval platform, optimizing:
1. **Retrieval Agent**: Dynamic Top-$K$, hybrid vector-lexical scoring, domain affinity boosting, and chunk parameter tuning.
2. **Prompt Design & Grounding**: Query-type tailored response synthesis, explicit source attribution, and strict refusal fallbacks.
3. **Agent Routing & Memory**: Context-aware intent classification, sliding-window turn decay, and cross-domain context isolation.
4. **Voice Interaction Reliability**: HTML5 Web Speech STT normalization, natural language speech cleaning, and cross-browser resilience.
5. **Before-vs-After Benchmarking**: Empirical comparison verifying significant performance enhancements.

## 🔬 Retrieval Optimization & Chunking Strategy

We evaluated three chunking configurations across 9 ground-truth benchmark queries spanning all three knowledge domains:

| Configuration | Chunk Size | Overlap | Total Chunks | Precision@1 | Recall@3 | MRR | Latency |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **Compact** | 400 chars | 50 chars | 50 | 77.8% | 77.8% | 0.778 | 1.15 ms |
| **Balanced** | 600 chars | 100 chars | 35 | 88.9% | 88.9% | 0.889 | 0.91 ms |
| **Optimized M4** | **800 chars** | **150 chars** | **28** | **100.0%** | **100.0%** | **1.000** | **0.81 ms** |

### Key Architectural Enhancements in Retrieval:
- **Hybrid Dense-Lexical Scoring**:
  $$S_{\text{hybrid}} = 0.55 \times S_{\text{vector}} + 0.45 \times S_{\text{lexical}}$$
  Combines semantic embedding distance with alphanumeric token intersection, eliminating false negatives for technical acronyms (e.g., AES, RSA, TCP, SVM).
- **Domain Affinity Boost**: Chunks whose ingested domain matches the query's detected domain receive a calibrated $+0.05$ score bonus.
- **Dynamic Top-$K$ Scaling**:
  - Factual: 4 chunks
  - Procedural / Multi-Part: 5 chunks
  - Comparative: 6 chunks

## ✍️ Prompt Engineering & Grounded Synthesis

### 1. Query-Type Tailored Response Formatting
- **Factual**: Direct definition and lead concept summary, followed by key properties and bulleted contextual details from secondary chunks.
- **Procedural**: Strict step-by-step numbering (`1. Step One`, `2. Step Two`), preserving operational sequence (e.g., TCP SYN -> SYN-ACK -> ACK, or Incident Response Preparation -> Detection -> Containment -> Lessons Learned).
- **Comparative**: Side-by-side dimensional contrast (Mechanisms, Architectures, Security Properties, Use Cases) highlighting trade-offs without hallucination.

### 2. Strict Grounding & Source Attribution
- Every factual claim is bound to its origin with inline citations:
  `- [DocumentName, Chunk X, Similarity: Y%]`
- When top retrieval similarity falls below threshold ($<0.30$), the system outputs an honest refusal fallback:
  *"No sufficiently relevant information was found in the knowledge base to answer your question."*

## 🎙️ Voice Interaction Reliability & Speech Sanitization

The `VoiceModule` transforms raw markdown responses into clean, natural auditory utterances for the Web Speech API:
- **Fenced Code Blocks**: Replaced with audible notices: `"Code snippet omitted for voice playback."`
- **Markdown & Citations**: Strips `#`, `*`, `_`, `[1]`, `[Citation 2]`, markdown links, and emojis.
- **Punctuation & Cadence**: Normalizes multiline breaks to clean pauses (`. `) to ensure smooth browser speech synthesis.
