# M3.1 — Clarification Agent Technical Specification & Evaluation

## 1. Overview & Objectives

The **Clarification Agent** (`milestone_3/app/agents/clarification.py`) is an autonomous multi-agent component in Milestone 3 designed to intercept queries that are ambiguous, incomplete, or contain multiple unresolved requirements before dense vector retrieval is attempted.

### Core Capabilities:
1. **Intelligent Ambiguity & Polysemy Detection**:
   - **Context-Aware Disambiguation**: Identifies domain keywords that have multiple distinct meanings (`tree`, `clustering`, `handshake`, `routing`, `model`, `layer`, `port`, `pipeline`). If the term is already qualified (e.g. `"Decision tree"`, `"Spanning tree protocol"`, `"B-tree"`, `"OSI transport layer"`, `"TCP 3-way handshake"`), it is recognized as **clear** and bypasses clarification.
   - **Antecedent-Aware Missing Context**: Identifies ungrounded pronouns (`it`, `this`, `that`, `its advantages`). If an antecedent entity is already present in the query (e.g. `"Explain TCP and its advantages"`), it proceeds directly without clarification.
   - **Incomplete Request Handling**: Detects truncated queries (`how to`, `compare SVM`, `what is the`, `difference between`, `how to configure with`) and generates targeted follow-up questions identifying the missing entity.
   - **Generic / Vague Terminology**: Flags non-specific terminology (`the algorithm`, `the protocol`, `the system`) lacking a named entity.
2. **Multi-Part Query Analysis**:
   - Decomposes multi-clause and multi-question inputs into individual sub-questions.
   - **Coherent / Related Multi-Part**: If sub-questions share a common domain context and are well-formed (e.g. `"What is TCP and what port does it use?"` or `"What is SVM and what are its kernel functions?"`), they proceed to retrieval without clarification.
   - **Ambiguous Multi-Part**: If one or more sub-questions are incomplete/ambiguous, or span 3+ completely disjoint topics, targeted clarification is triggered.
3. **Hardened State Management**:
   - Strict lifecycle tracking: `PENDING` -> `RESOLVED` / `CANCELLED`.
   - Rejects invalid or missing clarification IDs (`ValueError`).
   - Rejects repeated resolution attempts on already-resolved requests (`ValueError`).
   - Rejects empty/whitespace clarification inputs (`ValueError`).
4. **Context Retention & Query Refinement**:
   - Combines the original query context with the user's clarification response into a clean, disambiguated standalone query.
   - Pipes the refined query directly back into the existing M2 Query Understanding -> Retrieval -> Response Generation pipeline.

## 3. Disambiguation Catalog & Resolution Strategies

| Category | Example Trigger | Targeted Follow-Up Question | Refinement Behavior |
|---|---|---|---|
| `MULTIPLE_INTERPRETATIONS` | `"Explain tree"` | *"Which type of tree are you referring to?"* | Replaces polysemous term with selected domain specialization (`"Explain Decision Trees"`). |
| `MISSING_CONTEXT` | `"How does it work?"` | *"Which specific technology, algorithm, or networking protocol are you asking about?"* | Substitutes ungrounded pronoun with specified entity (`"How does TCP 3-way handshake work?"`). |
| `INCOMPLETE_REQUEST` | `"Compare SVM"` | *"Which algorithm or protocol would you like to compare 'SVM' against?"* | Appends missing comparison counterpart (`"Compare SVM vs Logistic Regression"`). |
| `AMBIGUOUS_TERM` | `"Explain the algorithm"` | *"Could you specify which exact algorithm, protocol, or concept you would like to explore?"* | Fuses specific algorithm into query. |
| `MULTI_PART_UNRESOLVED` | `"What is TCP, and also how to, and explain tree"` | *"Would you like to clarify the incomplete part, or focus on a specific sub-question first?"* | Isolates selected sub-question or clarifies ambiguous segment. |
| `INSUFFICIENT_INFORMATION` | `""` or `"thing"` | *"Please provide a specific question or topic you would like to look up."* | Prompts for concrete domain entity. |
