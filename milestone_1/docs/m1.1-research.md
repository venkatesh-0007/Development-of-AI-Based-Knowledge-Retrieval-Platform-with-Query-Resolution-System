# M1.1 — Research & Technical Understanding

## RAG
Retrieval-Augmented Generation (RAG) combines information retrieval with language generation. A query is converted into an embedding, semantically similar knowledge-base chunks are retrieved, and those chunks can be supplied as context to a language model.

## Chunking
Documents are divided into smaller chunks so retrieval can return focused context instead of entire documents. This implementation uses a configurable character-based chunk size with overlap and prefers natural text boundaries.

## Embeddings
An embedding is a numerical vector representing text in a semantic vector space. Similar meanings tend to have nearby vectors. The project uses Sentence Transformers with `all-MiniLM-L6-v2`.

## Vector Search
ChromaDB stores chunk embeddings and metadata. Queries are embedded using the same embedding model and searched using cosine distance.

## Multi-Agent Pattern
The planned agent roles are:
- Query Understanding Agent — interprets the incoming query.
- Retrieval Agent — obtains relevant chunks.
- Response Generation Agent — turns retrieved context into an answer.
- Clarification Agent — handles missing/unclear queries.
- Conversation Memory Agent — maintains conversation history.

Milestone 1 uses lightweight Python orchestration. A heavier agent framework can be introduced only if later milestones require it.

## Web Speech API
The browser Web Speech API can provide speech recognition and speech synthesis. It is planned as the voice interface around the text-based RAG pipeline.

## Architecture Decision
The implementation prioritizes a working ingestion and retrieval foundation before adding complex agent behavior or UI features.
